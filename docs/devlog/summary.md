# Devlog Summary

- 2026-09-06: **Art is data: heraldic blazons rendered by code** — owner chose heraldic flat vector, Guard on the second visual channel, and unique art per card. Those three combine better than they read separately, because heraldry has a formal description language: a card's art is a **blazon string in its own data file**, rendered to SVG by code, and there are no image assets at all. Unique-per-card then costs combinatorics over a charge library of thirty to fifty rather than 250 bespoke drawings; 250 blazons are a few kilobytes against 250 PNGs that would strain canon's blob ceilings; artwork changes diff as text; and coherence is structural because one renderer draws everything. It also answers the compression constraint that drove the whole question — at fifteen units a card is about seventy pixels and no illustration survives that, whereas vector scales losslessly. The premise that seventy pixels gives two channels turned out to be true only of arbitrary illustration: heraldry separates identity into four independent layers, so **Guard takes the card outline and bordure** (shape reads faster than colour at small size and competes with nothing), tribe keeps the field tincture, numbers keep the corners, and the charge is the only thing needing the expanded tier. Rule that follows: no information required for a turn decision may live only on hover. Correction landed in both AGENTS.md and the design: "card art pipelines" was written as a non-goal before `pixel_lab` and `badge` were checked — the owner has a working sprite pipeline and a precedent for 300 coherent generated concepts, so the claim was wrong as reasoned; the absence of a raster pipeline is now stated as a consequence of the blazon system rather than a goal. Badge's contact-sheet lesson is carried in explicitly: 250 devices get reviewed individually at native resolution in both tiers, never as a grid, with tincture collision checked per pair at real size under an animation overlay.
- 2026-09-06: **Review was on the wrong node, and worktrees were conflated with file disjointness** — two owner questions, both landing. The agent graph said "three lanes because three disjoint directories", which implies disjoint files are enough for concurrency; they are not. Disjoint files buy clean merges, **worktrees buy safe concurrent operation**, and agents sharing one working tree collide on the index, `HEAD`, `node_modules`, build output and ports regardless of which sources they touch — the index worst, since `git add -A` sweeps in another agent's half-finished edits and ships a message that lies about its contents. The rule is now written against concurrency rather than files: none for serial node 0, one per phase-1 lane with its own install, one per concurrent content author. On review: canon scales it to risk and that is defensible — uniform review is unweighted rather than more rigorous, and a review that always passes proves as little as a gate that always passes. But the allocation was wrong. Weighting by **blast radius times gate weakness** puts the highest-value review in the graph on **node 0, the contract**, which had none: a type contract cannot be tested at all and getting it wrong invalidates three downstream lanes before anyone notices. The inverse is content, where a mis-costed card passes every test and human judgement of balance is unreliable — simulation is the instrument there and reading is not. Verified and reviewed are now stated as distinct claims, since a node can honestly be one without the other.
- 2026-09-06: **The agent graph, after misreading the question** — "graph engineering" was read as graphics and then as the resolver's effect DAG; the owner meant how *agents* are organised to build the game, and ARCHITECTURE.md now carries that as its own section. The load-bearing points: the fan-out gate is the **contract**, not a working engine, so node 0 ships types, fixtures and throwing stubs and all three lanes start against them rather than serialising behind the hardest node; **fixtures are what decouple the lanes**, since render and sim can otherwise write code but verify none of it, which is deferred work wearing parallel work's clothes; **edges are commits on main, not messages**, because agents cannot see each other's chats or trees, so a design requiring two agents to talk has a node missing; **fan-out width is set by directory disjointness**, not ambition, and widening means making things disjoint rather than adding agents to contested files; the **event log is the render contract**, which forecloses the predictable collision where the render agent adds `isCurrentlyActing` to `GameState` and corrupts the determinism hash; **cycles collapse into one agent**, so content and balance cannot be two workers each invalidating the other; content authoring may fan out but **balance never does**, being a whole-pool property; the **effect vocabulary is frozen** and needing a verb escalates, or four authors invent four synonyms and the resolver grows four code paths; and **review is a node with an edge**, sitting between worker and integration, because a review after merge is a report rather than a gate. Nothing built or verified — this is a plan, and the graph is a hypothesis about where the seams are that each wave tests.
- 2026-09-06: **Engineering plan, and Echo does not terminate** — `ARCHITECTURE.md` now carries the module graph, the resolution-queue contract, the visual and balance requirements, and the delegation plan. Writing the resolver contract surfaced a defect in the design of record shipped hours earlier: `Echo` read "repeat the action of the unit that resolved immediately before me", and two adjacent Echoes walk backwards forever — reachable deliberately once an Echo Sigil exists, so an engine iteration cap would have turned a buildable combo into a crash. Fixed in the rule rather than the engine: Echo copies the previous unit's **base** action, which terminates by construction and reads as one line on a card. Generalised in both documents — a trait that reads another trait's output needs an explicit termination argument before it is written. Three other things worth keeping: the module graph is one rule (`engine` depends on nothing, everything depends on `engine`) and it is enforced as an import-boundary lint rule rather than an intention, alongside a ban on `Math.random` outside `engine/rng.ts`, because determinism is what makes replay, balance simulation and bug reproduction all possible at once. The unlimited board must **compress and never wrap**, since a second row destroys the left-to-right reading every adjacency trait depends on. And the design's central claim is falsifiable as a number: run an optimal-placement bot against a random-placement bot, and if their win rates match, placement is not a decision — that gap is the game's reason to exist and it can go red in CI. Its bound is stated with it: it measures bots, not whether the game is fun. Nothing is prototyped or verified; this is a plan.
- 2026-09-06: **The repo joins the fleet and gets a design** — `cards` had been failing fleet's census gate as `NOT IN THE CENSUS`, so it would never have received the canon at all; adding it took `sync-canon` from 23 to **24 current** with `npm test` 84/84 (`fleet` `a7bdf58`, `cards` `d6422a0`). Its AGENTS.md was authored around a block rendered by fleet's own `canon.mjs`, so it classified `current` on the first check rather than after a repair. The design was then settled by five rounds of structured interview and written to `docs/design/game.md`: manual placement with automatic left-to-right resolution, random targeting with Guard as the only redirect, an equipped hero acting last, unlimited board width, units/spells/equipment, class-based characters over racial tribes, and sigils carrying both card modification and the run-wide effects that would otherwise have been a separate relic system. Two owner answers changed the shape more than their length suggests. **Random targeting** dissolved the largest risk in the first draft, where lane targeting and cascade order were two positional systems competing for one placement decision — placement now means cascade only. **Unlimited board width** was assessed as high-risk and that assessment was wrong: the owner pointed out units require cards, which require drafting, and the arithmetic agrees — energy, hand size and deck composition cap the board near six to nine units in play and about fifteen at the extreme, so the board self-limits at roughly twice Hearthstone's width and deck design is the real dial. What survived the correction is narrower and more useful: **token generation** is the only route to a genuinely unbounded line, because summoned bodies bypass all three gates, so the budget discipline belongs there and not on the board rule. Cascade traits are adjacency-only for the same reason — a counting trait's ceiling is whatever the deck economy currently allows, which is not a number anyone controls directly. Nothing is prototyped; every number in the design is a reasoned starting guess and the document's first line says so.
