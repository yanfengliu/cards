# Devlog Summary

- 2026-09-06: **The measurement was right and the instrument was not** — four instrument defects an independent review found in the placement probe, all repaired, and the headline moved **up**. The gate that exists to defend the design's central claim could not go red on it: `npm run verify` set a non-zero exit for card-identity and determinism failures only, so a gap that collapsed to zero still exited 0 while `ARCHITECTURE.md` described it as "a number that can go red in CI". It now fails unless the paired 95% interval excludes zero **and** the gap reaches **5.00 pp**, two conditions that bind at opposite ends of the seed count — the interval is what keeps a 20-seed run from passing on luck, the floor is what keeps a 20,000-seed run from passing on 0.74 pp. The floor comes from the measurement's own null arms rather than from the headline: the cascade-stripped control runs 0.92 pp and the noise floor -0.26 pp, so a real collapse lands at or below about 1 pp, while the paired standard error at the gate's 400 seeds is 2.7 pp — 5.00 pp is one half-width above zero and 5.1 standard errors below the measured gap, so a false red needs a 5-sigma excursion. Three red proofs, and the third is the one that matters: run unmutated at `--encounter trivial --seeds 20000`, the interval is **1.28..1.83** and excludes zero, so the statistical condition passes on a gap a fortieth of the headline and only the floor fires. A gate written with the interval alone would have called that green. Then the search itself: it scored candidates under **independent** noise, four rollouts each, so it was ranking luck as often as arrangement. Switching to **common random numbers** — every candidate in one decision rolled out against the same targeting draws — is worth **+2.42 pp paired** (CI 1.89..2.94) over 20,000 seeds on its own, taking Bot A from 55.89% to 58.30% and the headline gap from **15.87 pp to 18.80 pp** (CI 18.06..19.53). The previously reported figure was *conservative*: the design claim is stronger than the probe reported, not weaker. Both bots were also stateful closures — a `salt` counter and a generator that outlived a fight — so a policy's decisions depended on its instance's lifetime, and the measurement reproduced only because `measure.ts` happens to construct one per fight. Hoisting that construction out of the loop for speed would have changed every placement and every final hash with every gate green. Both are now pure functions of the fight they are handed, and `src/sim/bots.test.ts` fails on a warmed instance, on a hoisted instance, and on a policy that answers the same question twice differently — all three go red against the previous revision. Last, `gate:banned-apis` learned `new Date()` and bare `Date()`, the same hidden input as the three names `ARCHITECTURE.md` happens to list. Scoped to `src/` and `test/` rather than exempting `tools/heraldry-probe/shoot.ts` by name, because `gate:boundaries` already makes `tools/` unreachable from the engine **by construction**, so a probe stamping its manifest with a timestamp needs no special case now or later. Its self-test counts per rule rather than in total, since a total-only count passes with one rule dead and the other over-firing — proved by breaking the clock detector and watching it exit 2. Every proof is in `docs/learning/gate-proofs.md`. One consequence for whoever integrates: `docs/work/1_turn-prototype/plan.md` and this log's own 15.87 pp entry are now the *old* instrument's numbers, and the difficulty sweep and per-trait ablation in that plan were all measured with the salted search.
- 2026-09-06: **34 green tests, 10 defects they could not see** — an independent review found the engine correct and the suite weak: of 28 mutations reintroducing a defect the code or docs claim to prevent, ten left `npm test` at 34/34. Six of the ten were the resolver's ordering contract, and the reason they were invisible is more interesting than an oversight — they are **unobservable with the shipped pool**. Every trigger in the game is keyed to one uid, so no event can ever match two units and the board-order loop decides nothing; no effect both spawns a continuation and produces an event anything reacts to, so the order of those two queue pushes decides nothing either. Reverse the trigger loop, order it by uid, turn the queue into a stack, defer the death checkpoint to the end of the drain, read the acting order live, swap continuations with reactions: all six were free. `test/resolver-order.test.ts` now gates each one, **every test watched going red under its own mutation**, with the failures in `docs/learning/gate-proofs.md`. Three of the six needed a trigger that fires for more than one unit and the game has none, so `drain` and `resolvePhase` took an optional `extraTriggers` parameter that defaults to null and that production never passes — the one non-behavioural engine change here, made because a gate nobody can make go red is not a gate. The **within-unit tie-break was documented nowhere**: a unit carrying both Relay and Ward grants the power before the ward purely because Relay's `if` block is written first, and that sentence now lives in `triggersFor` with a test holding it. Two existing tests were passing for the wrong reason and are rewritten: the Guard-targeting test built its generator and threw it away, then indexed the target list with `i * 7919 % 2`, which alternates whatever the resolver does — it passed with `pick` stubbed to always return the first element; and "no unit acts after dying" took the unit off the board before the phase, so it exercised the phase loop's skip rather than the guard in `apply`, which could be deleted outright with the suite green. `cloneFight` **aliased both deck arrays**, so every lookahead rollout held a handle on the live fight's deck — harmless only until the first mill, shuffle-in or tutor effect, now copied and gated. Wake stays inert by the owner's decision, but a test now carries the whole sequence to the swing, so deleting the trait and fixing it **both go red** instead of a dead trait sitting behind a green assertion. Structurally, `ARCHITECTURE.md`'s one-way content → engine arrow was a cycle in the code: a fight is now handed a `CardPool` and the engine imports nothing, with `gate:boundaries` extended to name `src/content/` and its self-probe widened to prove it fires for **every** forbidden prefix rather than once in total. Behaviour held still and it was checked rather than asserted: `npm run verify` is byte-identical before and after, every win rate, gap and interval unchanged.
- 2026-09-06: **The gates the docs had been promising, made to go red** — three debts left by the two probes that landed this morning, all paid. `AGENTS.md` had a Gates section that was still a placeholder saying "no code, so no code gates" next to a repo with an engine, 34 tests and a simulation runner; it now lists only commands that exist and were run, and it says in as many words that **there is no lint gate and no format gate because there is no linter and no formatter** — a Gate written ahead of its command is the failure that section exists to prevent, and writing one now would have been the whole point missed. `exactOptionalPropertyTypes` went back to `true`, relaxed during integration because two sites assigned `undefined` explicitly against non-optional targets; both are fixed by conditional spread rather than a cast, because "this card has no bordure" means the key is absent, not present-and-undefined. Then the two gates `ARCHITECTURE.md` has been asking for since the day it was written: `npm run gate:boundaries` fails when anything under `src/engine/` imports from `src/render/`, `src/ui/` or `tools/` or references a `lib.dom`-only global, and `npm run gate:banned-apis` fails when `Math.random`, `Date.now` or `performance.now` appears outside `src/engine/rng.ts`. **Both were made to go red before being believed**, and the proofs are in `docs/learning/gate-proofs.md` with the mutations and the exact failures. The interesting finding is why they parse instead of grepping: on a completely clean tree, `grep` for those three names returns **16 hits and zero real calls**, because `rng.ts` and `measure.ts` both name all three in comments in order to say they are never called. A grep gate would have been red on arrival and then deleted or exempted into uselessness — a check built from the same symbol as the thing it checks proves only that the text agrees with itself. Both gates use the TypeScript compiler already in `devDependencies`, so no new package, and both carry the same two habits: a bound in the file header saying what a green run does not prove, and a probe they must make their own detector fire on before they will report an absence, so "did not run" cannot come back as "passed". The dependency-audit gate is `npm run audit` and sits deliberately **outside** `npm run gates`, because it reaches the registry and an offline machine would otherwise turn the per-commit gate red for a reason that has nothing to do with the code. One overlap recorded rather than churned: `test/determinism.test.ts` already had a line-regex version of the banned-API check, weaker on three axes, left alone because the prototype is under independent review at this revision.
- 2026-09-06: **70px heraldry works, and the thing that failed was not the thing we were watching for** — the first code in the repo: an SVG heraldry renderer driven by blazon strings in card data (`src/render/heraldry/`, eight charges, two tiers), sixteen fixture cards, and a Playwright probe that shot 158 views at two device scale factors. Every one of the sixteen was inspected individually at native resolution in both tiers on both grounds, per canon; the rows were used only for the adjacency question they actually answer. **The premise holds.** All four channels read at 70 device pixels, and Guard-on-the-silhouette is the strongest by a wide margin — a shield among rectangles is countable at a glance in a fifteen-card row. All six tribe pairs are separable at real size on both grounds. `ARCHITECTURE.md`'s instruction to check pairs visually rather than by palette is vindicated by its own numbers: dwarf-vs-human computes to **1.07:1 luminance contrast**, which would condemn one of the easiest discriminations on the board. What failed was a collision nobody was watching for — not two tribes against each other but **sable against the dark board**. The card outline `#0d0d12` is darker than both a `#26262b` field and a `#15171c` background, so a non-Guard dragon card has no edge at all: three of fifteen cards in the dark row simply are not there, and every adjacency trait depends on seeing which card is next to which. It is an outline defect, not a palette defect, and a pale mount stroked outside the dark outline fixes it on both grounds at no cost — verified against the same fifteen cards at the same size. Two smaller amendments: bordures should default to **or**, because an argent bordure merges with a light background, and the charge earns its place in the **compressed** tier rather than waiting for hover, since the eight stayed separable at 70px. The real floor is about **60 device pixels** and it is set by the numerals — silhouette and tincture survive to 44px and below, so if the board ever compresses further it is the numbers that need redesigning, not the heraldry. Four renderer defects were caught only by looking: a near-360° arc leaving a stray ring, a crescent that cannot be built as disc-minus-disc under either fill rule, a mount clipped away by the SVG viewport with no error, and two charges that read as a blob and a scarecrow. Bounds stated: no animation overlay, no human eye, eight charges rather than fifty, and no colour-vision-deficiency check — tribe is carried by hue and deuteranopia would likely collapse gules against vert.
- 2026-09-06: **Placement is a decision, and it is Ward that makes it one** — the first code in the repo: a headless deterministic prototype of one fight (`3209bbe`), built to answer the design's central falsifiable claim by observation. Over **20,000 seeded fights**, a bot that searches insertion positions wins **55.89%** against **40.02%** for a bot that places at random — a paired gap of **15.87 pp** (CI 15.13..16.61) against a measured noise floor of **0.04 pp** (CI -0.69..0.77), where the noise floor is two random-placement bots differing only in their placement stream. The methodology is the whole result, so it is verified rather than argued: card selection is a pure function of hand and energy that never reads the board, both arms receive the already-chosen card list and return only insertion indices, and deck shuffling runs on a **separate RNG stream** from targeting so that a placement changing how many targeting rolls a fight consumes cannot shift the draw order. The harness re-derives that from the runs — same hand, same cards, same order over **122,420 compared rounds** — and separately confirms the arms actually placed differently (51.6% of placed cards went to a different slot), because a same-cards check also passes when nothing differed. Three things the measurement was not looking for. **The gap is difficulty-dependent**, 17.78 pp on the hard encounter down to 1.08 pp on the trivial one, so any single figure is a figure about an operating point. **The negative control is the finding that matters**: strip Relay, Ward and Wake and the gap collapses to 0.40 pp at a 62% baseline — nowhere near a floor — so act order alone is worth about 1 pp and the adjacency traits are the entire effect, which is what the design says and now has a number. And **Ward, not Relay, carries most of it**: at matched baselines removing Ward more than halves the gap while removing Relay barely moves it. The design already contained the reason — its own worked example says Relay's flat +2 goes somewhere either way and only the packaging changes — so the decision is real but it is mostly about protection rather than buff routing. Then a design defect the prototype found by accident: ablating **Wake** changed the outcome of not one fight in 20,000, because a player unit can only die while the enemy is attacking and the enemy attacks after the player's whole line has resolved. Measured directly: **0** player-side deaths during the player's own phase against 1,111 during the enemy's, with 59 Wake grants all arriving after their unit had acted. Wake works only for the side that resolves second, which is structural rather than a numbers problem, and fixing it is a rule change the owner owns. Two smaller gaps recorded rather than patched: the design's worked example never says what keeps player attacks off the enemy hero, which its own targeting rule makes a legal target, so the example does not reproduce as written; and Ward's timing is unspecified, which matters more than it looks now that Ward turns out to be the load-bearing trait. Bounds stated with the claim: this measures bots, Bot B places uniformly at random and no human does, and against a naive fixed rule — always append beside the hero — the gap is 9.47 pp, which is the better guide to what placement is worth to someone not thinking about it. Nothing here says the game is fun.
- 2026-09-06: **Art is data: heraldic blazons rendered by code** — owner chose heraldic flat vector, Guard on the second visual channel, and unique art per card. Those three combine better than they read separately, because heraldry has a formal description language: a card's art is a **blazon string in its own data file**, rendered to SVG by code, and there are no image assets at all. Unique-per-card then costs combinatorics over a charge library of thirty to fifty rather than 250 bespoke drawings; 250 blazons are a few kilobytes against 250 PNGs that would strain canon's blob ceilings; artwork changes diff as text; and coherence is structural because one renderer draws everything. It also answers the compression constraint that drove the whole question — at fifteen units a card is about seventy pixels and no illustration survives that, whereas vector scales losslessly. The premise that seventy pixels gives two channels turned out to be true only of arbitrary illustration: heraldry separates identity into four independent layers, so **Guard takes the card outline and bordure** (shape reads faster than colour at small size and competes with nothing), tribe keeps the field tincture, numbers keep the corners, and the charge is the only thing needing the expanded tier. Rule that follows: no information required for a turn decision may live only on hover. Correction landed in both AGENTS.md and the design: "card art pipelines" was written as a non-goal before `pixel_lab` and `badge` were checked — the owner has a working sprite pipeline and a precedent for 300 coherent generated concepts, so the claim was wrong as reasoned; the absence of a raster pipeline is now stated as a consequence of the blazon system rather than a goal. Badge's contact-sheet lesson is carried in explicitly: 250 devices get reviewed individually at native resolution in both tiers, never as a grid, with tincture collision checked per pair at real size under an animation overlay.
- 2026-09-06: **Review was on the wrong node, and worktrees were conflated with file disjointness** — two owner questions, both landing. The agent graph said "three lanes because three disjoint directories", which implies disjoint files are enough for concurrency; they are not. Disjoint files buy clean merges, **worktrees buy safe concurrent operation**, and agents sharing one working tree collide on the index, `HEAD`, `node_modules`, build output and ports regardless of which sources they touch — the index worst, since `git add -A` sweeps in another agent's half-finished edits and ships a message that lies about its contents. The rule is now written against concurrency rather than files: none for serial node 0, one per phase-1 lane with its own install, one per concurrent content author. On review: canon scales it to risk and that is defensible — uniform review is unweighted rather than more rigorous, and a review that always passes proves as little as a gate that always passes. But the allocation was wrong. Weighting by **blast radius times gate weakness** puts the highest-value review in the graph on **node 0, the contract**, which had none: a type contract cannot be tested at all and getting it wrong invalidates three downstream lanes before anyone notices. The inverse is content, where a mis-costed card passes every test and human judgement of balance is unreliable — simulation is the instrument there and reading is not. Verified and reviewed are now stated as distinct claims, since a node can honestly be one without the other.
- 2026-09-06: **The agent graph, after misreading the question** — "graph engineering" was read as graphics and then as the resolver's effect DAG; the owner meant how *agents* are organised to build the game, and ARCHITECTURE.md now carries that as its own section. The load-bearing points: the fan-out gate is the **contract**, not a working engine, so node 0 ships types, fixtures and throwing stubs and all three lanes start against them rather than serialising behind the hardest node; **fixtures are what decouple the lanes**, since render and sim can otherwise write code but verify none of it, which is deferred work wearing parallel work's clothes; **edges are commits on main, not messages**, because agents cannot see each other's chats or trees, so a design requiring two agents to talk has a node missing; **fan-out width is set by directory disjointness**, not ambition, and widening means making things disjoint rather than adding agents to contested files; the **event log is the render contract**, which forecloses the predictable collision where the render agent adds `isCurrentlyActing` to `GameState` and corrupts the determinism hash; **cycles collapse into one agent**, so content and balance cannot be two workers each invalidating the other; content authoring may fan out but **balance never does**, being a whole-pool property; the **effect vocabulary is frozen** and needing a verb escalates, or four authors invent four synonyms and the resolver grows four code paths; and **review is a node with an edge**, sitting between worker and integration, because a review after merge is a report rather than a gate. Nothing built or verified — this is a plan, and the graph is a hypothesis about where the seams are that each wave tests.
- 2026-09-06: **Engineering plan, and Echo does not terminate** — `ARCHITECTURE.md` now carries the module graph, the resolution-queue contract, the visual and balance requirements, and the delegation plan. Writing the resolver contract surfaced a defect in the design of record shipped hours earlier: `Echo` read "repeat the action of the unit that resolved immediately before me", and two adjacent Echoes walk backwards forever — reachable deliberately once an Echo Sigil exists, so an engine iteration cap would have turned a buildable combo into a crash. Fixed in the rule rather than the engine: Echo copies the previous unit's **base** action, which terminates by construction and reads as one line on a card. Generalised in both documents — a trait that reads another trait's output needs an explicit termination argument before it is written. Three other things worth keeping: the module graph is one rule (`engine` depends on nothing, everything depends on `engine`) and it is enforced as an import-boundary lint rule rather than an intention, alongside a ban on `Math.random` outside `engine/rng.ts`, because determinism is what makes replay, balance simulation and bug reproduction all possible at once. The unlimited board must **compress and never wrap**, since a second row destroys the left-to-right reading every adjacency trait depends on. And the design's central claim is falsifiable as a number: run an optimal-placement bot against a random-placement bot, and if their win rates match, placement is not a decision — that gap is the game's reason to exist and it can go red in CI. Its bound is stated with it: it measures bots, not whether the game is fun. Nothing is prototyped or verified; this is a plan.
- 2026-09-06: **The repo joins the fleet and gets a design** — `cards` had been failing fleet's census gate as `NOT IN THE CENSUS`, so it would never have received the canon at all; adding it took `sync-canon` from 23 to **24 current** with `npm test` 84/84 (`fleet` `a7bdf58`, `cards` `d6422a0`). Its AGENTS.md was authored around a block rendered by fleet's own `canon.mjs`, so it classified `current` on the first check rather than after a repair. The design was then settled by five rounds of structured interview and written to `docs/design/game.md`: manual placement with automatic left-to-right resolution, random targeting with Guard as the only redirect, an equipped hero acting last, unlimited board width, units/spells/equipment, class-based characters over racial tribes, and sigils carrying both card modification and the run-wide effects that would otherwise have been a separate relic system. Two owner answers changed the shape more than their length suggests. **Random targeting** dissolved the largest risk in the first draft, where lane targeting and cascade order were two positional systems competing for one placement decision — placement now means cascade only. **Unlimited board width** was assessed as high-risk and that assessment was wrong: the owner pointed out units require cards, which require drafting, and the arithmetic agrees — energy, hand size and deck composition cap the board near six to nine units in play and about fifteen at the extreme, so the board self-limits at roughly twice Hearthstone's width and deck design is the real dial. What survived the correction is narrower and more useful: **token generation** is the only route to a genuinely unbounded line, because summoned bodies bypass all three gates, so the budget discipline belongs there and not on the board rule. Cascade traits are adjacency-only for the same reason — a counting trait's ceiling is whatever the deck economy currently allows, which is not a number anyone controls directly. Nothing is prototyped; every number in the design is a reasoned starting guess and the document's first line says so.
