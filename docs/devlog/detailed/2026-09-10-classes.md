## What was believed and proved false

**"The gates are proven, because the tests say so in their own comments."** `test/hero-attacks.test.ts` and `test/classes.test.ts` arrived carrying eleven `Mutation watched going red:` comments naming specific defects. The worker that wrote them died to a rate limit before running any of them. A sentence a gate carries about itself is not evidence, and reading those comments as evidence is the exact failure `docs/learning/gate-proofs.md` exists to prevent. Fifteen mutations were applied at this revision and all fifteen went red, so the claims turned out to be true — but they were unproven for two commits, and the file that records them now is the artefact, not the comments.

**"A mutation runner that reports success applied the mutation."** Eight of the fifteen mutations matched nothing on the first pass. Every source file in this repo is CRLF and the anchors were written with `\n`, so single-line anchors matched and multi-line anchors did not. The runner asserts each anchor occurs exactly once before writing anything, which turned eight silent no-ops into eight refusals. Without that assertion the run would have mutated nothing, run a clean tree, come back green, and eight gates would have been written down as unprovable. **A no-op edit and a gate that cannot fail produce the same green.** The same assertion caught `const cls = classOf(content, classId);` occurring in both `startRun` and `contentForClass`.

**"Volley has one way to be wrong."** It has two, and they fail on opposite halves. Writing it as one attack at doubled Power keeps the event count right and gets the damage wrong; writing it as two swings inside one `apply` keeps the damage right and gets the checkpoint wrong, so a body killed by the first swing's retaliation swings again from off the board. Only two separate `attack` effects — the shipped shape — survives both mutations. A gate proving one of them would have looked exactly as green while the other was live.

**"A `--verify` run that exits non-zero is a code failure."** `node src/sim/runmeasure.ts --verify --class mage` exits 1 at 200 seeds, on the eighth check, "the instrument can see a difference". Nothing is broken. The check asks whether the seed window has the power to detect a change, and an arm that wins nothing has none. `npm run verify:run` runs the Knight and is green. The gate's own message draws the distinction — "Either the content is unwinnable by this bot or the seed window is too small" — and the 1000-seed measurement settles which: the Mage won 0 of 1000 at all four arms, so it is not a seed-window artefact.

## The numbers, which are information and not targets

`npm run measure:run -- --class <id>`, 1000 contiguous seeds 1..1000 per class, strongest arm (greedy route, search placement). The instrument was checked before the numbers were read: each report's header names its own hero and Health, so the flag took effect.

|---|---|---|---|---|---|---|---|---|
| Knight | 200 | 16.50% (165/1000) | 14.33%..18.93% | 2.03 | 11.78 | 8.40 | 100.00% | 86.50% |
| Ranger | 180 | 0.30% (3/1000) | 0.10%..0.88% | 1.21 | 7.68 | 7.41 | 97.20% | 24.49% |
| Mage | 160 | 0.00% (0/1000) | 0.00%..0.38% | 0.79 | 6.01 | 11.57 | 72.80% | 8.10% |

Where they end: the Knight mostly dies to the act-3 boss (23.7% of all runs) after clearing two acts; the Ranger and the Mage mostly die to an ordinary act-2 fight (43.7% and 49.3%). The Mage is the only class that regularly fails to clear act 1 — 27.2% of its runs end there.

The Mage's `mean rounds/fight` is the number that says why. At 11.57 it is three rounds longer than the Knight's 8.40, against a 20-round cap that then turns into a timeout: a 1-Power swing plus a 1-point burn, and every enemy from the Shieldwall up carries Armour 1, which stops the burn completely. The Mage's own file says the burn is meant to work while the line keeps it alive; for this bot the line does not.

`docs/policies/local-rules.md` is why nothing was changed in response. No cost, stat or pool weight moved. These are also a claim about one bot and not about a player — the router is greedy and the placement bot searches one turn ahead.
