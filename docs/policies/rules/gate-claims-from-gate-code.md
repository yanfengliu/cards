# A sentence about what a gate catches is written from that gate's code

One of [cards' local rules](../local-rules.md).

**A sentence that says what a gate catches is written from that gate's code and names only what the code compares, plus what it does not. A claim is widened only after the code is.** That covers the Gates section of `AGENTS.md`, a gate's own header, doc comments and failure text, a test's name and message, and the devlog and plan sentences that describe a gate.

**Why.** Three reviews in a row found a claim bigger than its gate. Each fix grew the check and rewrote the claim, and each new claim outran the new check. The run-layer review of `9b36329` found a test that said fights are handed the class's hero while it compared `run.content.hero`. The round that closed it, `1a72436`, wrote into `AGENTS.md` that `verify:run` fails when "the fight setup the run hands the engine is not its content plus its ledger", and that the check "walks every field of each resolved card and of the hero off the objects, so a race, a name or a hero's traits that nothing granted cannot move on the way in either". Finding D of the final acceptance review of `907c8e9` found that true of one setup, at an ordinary fight: card sigils stripped from every elite and boss fight changed 129 of 360 runs and passed all seven gates. Its close, `0a1c8fd`, added `watchFights` and wrote that `verify:run` fails when "a fight the run hands the engine is not its content plus its ledger or no ordinary fight, elite or boss was fought holding both kinds of sigil". The re-review of `2b040d9` found each part bigger than the code: of the enemy side the check compares the enemy hero's Power and Armour alone, a fight's hero is read through five fixed fields, and the population needs one fight with each kind of sigil, not one fight with both. There is always more of a fight to check, so growing the check to meet the sentence never ends. The fourth round, `9d84e7f`, narrowed each sentence to its code instead.

**Bound.** This governs wording, not coverage. Whether a gate should check more is a separate decision, made on its own evidence, and the claim may grow once the code has. It is a rule, not a gate: no check here can read a sentence beside the code it describes and say whether they agree, so a review is what catches a breach.
